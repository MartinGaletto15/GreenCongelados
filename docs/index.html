Alcance funcional

Qué podés probar

La API cubre el flujo completo de una tienda de congelados, desde el catálogo hasta la entrega.

01

Catálogo y stock

Productos, categorías, visibilidad y stock derivado del estado real de cada artículo.

02

Carrito y checkout

Validación de stock, cupón, costo de envío y creación de la orden en una operación atómica.

03

Logística

Asignación de cadete, cambios de estado y cancelación con restitución de stock.

04

Cuentas y roles

JWT, SUPERADMIN, ADMIN, USER y CADET con permisos separados.

Rol Email Contraseña Permisos

Paso obligatorio

Dirección de envío

El checkout no funciona sin una dirección cargada. El usuario demo ya tiene Córdoba 1234, 4A. Si usás otra cuenta, registrás un usuario nuevo o borraste la dirección, creala antes de comprar.

GET /api/addresses/me

Si responde 404 con ADDRESS_NOT_FOUND

Creá la dirección con POST /api/addresses:

POST /api/addresses application/json 
{
  "street": "Córdoba 1234",
  "dpto": "4A",
  "references": "Timbre 4A"
}

Si responde 409 con ADDRESS_ALREADY_EXISTS

Ya existe una dirección. Actualizala con PUT /api/addresses:

PUT /api/addresses application/json 
{
  "street": "San Luis 456",
  "dpto": "2B",
  "references": "Portón negro"
}

Hay una sola dirección por usuario. El PUT es parcial: los campos null conservan el valor actual.

Tres rutas

Recorrido sugerido

Tres recorridos independientes para probar la API de punta a punta. Cada uno empieza con un login distinto; usá el token en Authorize antes de seguir.

Ruta 01

Como cliente

USER

Catálogo, carrito, dirección y checkout con el usuario demo.

  1. 1

    Login y copiar el token

    Autenticate con user@greencongelados.com / User1234.

    POST /api/auth/login application/json 
    {
  "email": "user@greencongelados.com",
  "password": "User1234"
}
  2. 2

    Autorizar Swagger

    Copiá el token de la respuesta y pegalo en Authorize, sin la palabra Bearer. Swagger agrega el prefijo.

  3. 3

    Verificar la dirección

    Si no existe, seguí el aviso de arriba: POST /api/addresses.

    GET /api/addresses/me
  4. 4

    Explorar el catálogo

    Productos y categorías son públicos.

    GET /api/products
    GET /api/categories
  5. 5

    Agregar un producto al carrito

    POST /api/cart/items application/json 
    { "idProduct": 1, "quantity": 2 }
  6. 6

    Revisar el carrito

    GET /api/cart/items
  7. 7

    Crear la orden

    POST /api/orders application/json 
    { "couponCode": "BIENVENIDO10" }
    Cupón demo BIENVENIDO10
  8. 8

    Consultar tus pedidos

    GET /api/orders/me

El checkout no cobra: crea la orden y descuenta stock. El cupón BIENVENIDO10 aplica 10% con un mínimo de $5.000.

Ruta 02

Como cadete

CADET

Pedidos asignados y transiciones logísticas del cadete demo.

  1. 1

    Login como cadete

    POST /api/auth/login application/json 
    {
  "email": "cadet@greencongelados.com",
  "password": "Cadet1234"
}
  2. 2

    Ver los pedidos asignados

    El cadete solo ve los pedidos que tiene asignados.

    GET /api/users/cadets/me/orders
  3. 3

    Marcar el pedido en camino

    El body es un string JSON, no un objeto.

    PATCH /api/users/cadets/me/orders/{idOrder}/status
    PATCH /api/users/cadets/me/orders/{idOrder}/status application/json 
    "InDelivery"
  4. 4

    Confirmar la entrega

    Repetí el PATCH con el estado "Delivered".

    PATCH /api/users/cadets/me/orders/{idOrder}/status
    PATCH /api/users/cadets/me/orders/{idOrder}/status application/json 
    "Delivered"

Flujo logístico: el pedido pasa de LogisticsPending a InDelivery y luego a Delivered. La cancelación restituye stock.

Ruta 03

Como admin

SUPERADMIN

Asignación de cadetes, vista global de pedidos y gestión de catálogo.

  1. 1

    Login como superadmin

    POST /api/auth/login application/json 
    {
  "email": "superadmin@greencongelados.com",
  "password": "Super1234"
}
  2. 2

    Obtener el ID del cadete

    GET /api/users/cadets
  3. 3

    Asignar un pedido

    Usá el id del cadete y el idOrder de un pedido.

    PUT /api/users/cadets/{id}/orders/{idOrder}
  4. 4

    Ver todos los pedidos

    GET /api/orders
  5. 5

    Crear un producto

    POST /api/products application/json 
    {
  "name": "Mango demo",
  "descriptionShort": "Mango en cubos.",
  "price": 4200,
  "currentStock": 20
}
  6. 6

    Ocultar el producto

    Ocultalo sin borrar el historial de pedidos.

    PATCH /api/products/{id}/hide

Rol SUPERADMIN: además de la logística, administra usuarios, roles, productos, categorías, promociones y envío.

Bajo el capó

Qué mirar en el código

Decisiones de diseño pensadas para que el stock, las sesiones y los errores sean confiables.

  1. 01

    Clean Architecture

    Domain, Application, Infrastructure y Web. La dirección de dependencias va hacia el dominio; las reglas de negocio no conocen EF Core ni ASP.NET.

  2. 02

    Stock atómico

    ExecuteUpdateAsync con WHERE CurrentStock >= cantidad para no vender dos veces la última unidad. Ver ADR 0001.

  3. 03

    Sesiones JWT con security_stamp

    Cambiar el rol o la contraseña invalida los tokens al instante. Ver ADR 0002.

  4. 04

    Estado de producto derivado del stock

    Available y OutOfStock se calculan desde el stock; Hidden y Deleted son decisiones explícitas. Ver ADR 0003.

  5. 05

    Errores uniformes y seeder idempotente

    Todas las respuestas de error siguen el contrato { error, code }. El seeder carga datos demo sin duplicar si la base ya tiene usuarios.

Alcance de la demo

Limitaciones de la demo

Es un entorno de prueba técnica: está pensado para evaluar la API, no para operar una tienda real.

Datos ficticios y persistentes. No hay reset automático: la base demo se comparte entre visitantes.

Sin pasarela de pagos: el checkout crea la orden, no cobra.

Sin frontend: Swagger es la interfaz para probar todos los endpoints.

El envío de correos depende de la configuración SMTP. Sin credenciales, algunos mails no salen.

No uses datos personales reales. La demo es pública y las cuentas son compartidas.
